# Trend 策略代码改造计划 — 对齐 spec 的吸收与简化实施方案

> **交付性质**：改造计划本身，不含任何实际代码改动（执行需另行确认）。
> **spec**：`trend_strategy.md`（2026-09 版策略规格，模块引用路径以它为准）。
> **两次问题**：①「分析 trend 策略如何吸收和改进 cycle 策略，cycle 从美股迁移而来应符合 A 股情况，trend 已有代码实现，吸收要能落地」→ 已交付诊断/设计/回测（《Trend吸收Cycle改进报告》）；②「分析 trend 有而 cycle 没有的部分，识别必要/无效/有害/性价比不高」→ 已交付四分类台账（《Trend简化决策报告》，56 条：必要 31 / 无效 15 / 有害 2 / 性价比 8）。
> **现在代码**：两层——(a) **真实代码库**（交易机）：spec 引用的 `src/market_state/market_gate.py`、`src/trend/report.py`、`src/trend/veto_rules.py`、`src/trend/sell_rules.py`、`signal_detector`、`trend_sell.py` 等，本工作区不可直接读取，路径与现状描述以 spec 文档记载为准；(b) **已验证参考实现**（本工作区 `cycle-absorption/` 包）：全部吸收组件与约束回测引擎，逐函数可引用（file:line），是改造项的落地模板与行为基准。
> **改造目标**：把两次问题的结论落进真实代码库——吸收 5 组件（A1/A2/B1/C1/D1）、移除 2 有害 + 8 无效项、降级 8 性价比项，且全程最小侵入、开关化、可回滚。

## 4. 分阶段改造步骤（P0-P5）

**总原则**：每批一个可独立回滚的开关；每批影子验证 2 周（新逻辑计算并展示、不拦截实际交易）后再切拦截；任何一步失败回退到上一批末状态。

**P0 基线与防护**（1-3 日 + 3 交易日观察）
- P0.1 分支与行为基线快照 → P0.2 配置开关骨架（默认全关）→ P0.3 组件单测模板
- 验证：**等价性验证**——全关状态连续 3 个交易日日报/卖出单与基线逐字节一致（本包 `selfcheck.py` 的 switch_equivalence 已在重建层证明该模式可行）；`pytest tests/` 全绿
- 回滚：删分支/删配置节

**P1 减法批 1：有害项**（各 0.5 天 + 影子 2 周）
- P1.1 移除条件④（含评分重分配）→ P1.2 移除 V9
- 验证：新旧信号重合度报告；方向核对消融预期（改进版 ΔCAGR +6.3pp/+1.4pp）；单测更新
- 回滚：开关恢复（保留一个版本周期）

**P2 减法批 2：无效项**（各 0.5 天 + 影子 2 周）
- P2.1 V2/V3/V6 → P2.2 V7（保留⑥b 注记）→ P2.3 K 组 → P2.4 X1/X6（依赖 P3.3，可调序至 B1 之后）→ P2.5 文案层（可选）
- 验证：拦截/信号/卖出动作差集报告（V2/V3/V6/V7 预期空集）
- 回滚：开关恢复

**P3 吸收加法**（约 3 天编码 + 影子 2 周×2 批）
- P3.1 cycle_stage.py → P3.2 cap/override 接线（影子展示→切拦截）→ P3.3 B1 合并+状态落盘 → P3.4 C1/D1 过滤 → P3.5 防误删注记
- 验证：组件单测（P0.3 模板）；影子期日报输出 stage/cap 与延伸动作；人工抽查 K 线
- 回滚：逐开关回退（等价性已验证全关=现状）

**P4 参数与口径简化**（各 0.5 天 + 影子 A/B 2 周）
- P4.1 G5 双轨统一 → P4.2 X4 系数 A/B（0.90/0.92/关闭三档）→ P4.3 ⑥瘦身 → P4.4 V5/X3 降级+V5 观察标注
- 验证：影子 A/B 对比报告（复用 research/trend_bt 配对口径）
- 回滚：参数回原值

**P5 收尾**（1.5 天）
- P5.1 spec 文档更新（吸收章节+删除注记+证据链接）→ P5.2 台账闭环

# 价格循环策略（Cycle of Price Action）— 研究契约

> 状态：**研究中，未上线，零生产预算，不自动下单。**
>
> 本文定义未来独立 Cycle 策略的边界；它不描述当前 `src/trend/` 的交易规则。原始方法清单保留在 [Cycle of Price Action.md](./Cycle%20of%20Price%20Action.md)，仅作研究参考，不等于项目已实现或已验证的规则。

## 一、策略定位

价格循环交易的假设不是“均线多头后的缩量回踩会续涨”，而是价格会在恐慌、修复、趋势延伸、衰竭和下行等阶段间转换；阶段转换可以产生有定义的风险收益比。

它应回答四个独立问题：

1. 指数和个股各自处于什么阶段，谁决定交易方向？
2. 哪个阶段是观察、试仓、加仓、减仓或清仓，而非仅给一个标签？
3. 何种确认使“恐慌”从抄底猜测变成右侧修复？
4. 阶段误判、跳空和涨跌停时，损失如何受限？

## 二、与趋势回踩的关系

| 对比 | 趋势回踩（已运行） | 价格循环（待研究） |
|---|---|---|
| 核心假设 | 上升趋势的回调后续涨 | 阶段转换提供波段机会 |
| 首要形态 | 缩量回踩 MA5/MA10 | 恐慌修复、楔形/平台突破、延伸衰竭等 |
| 市场门控 | 五态 `market_gate` 是常规开仓前提 | 必须自行验证是否需要以及如何使用 gate |
| 仓位 | 单笔风险预算，现有 overlay 可截断 | 必须定义阶段对应的风险预算 |
| 绩效归因 | 个股回踩续涨 | 阶段识别和转换本身 |

两者可以共享行情、指标、通知、模拟仓和持仓工具；不能共享“信号成立”的定义，也不能把一个策略的过滤器视为另一个策略的回测结果。

## 三、当前已有的不是 Cycle 策略

当前代码只把以下规则作为趋势回踩的**风险叠加层**：

| 组件 | 位置 | 当前作用 |
|---|---|---|
| A1 | `src/market_state/cycle_stage.py` | 指数偏离 MA10 过大时，将趋势回踩的新开仓组合上限压至 30% |
| A2 | 同上 | 恐慌后收复 MA10 的当日，允许受 40% 上限约束的例外开仓 |
| B1 | `src/pullback_trend/cycle_overlay.py` / `sell_rules.py` | 个股多次延伸时分批止盈 |
| C1 | `src/pullback_trend/cycle_overlay.py` | ATR 扩张日过滤趋势回踩信号 |
| D1 | 同上 | MA5 向下时过滤趋势回踩信号 |

这些规则没有构成独立的标的选择、入场、退出和组合流程，故不能作为 Cycle 策略的实盘或回测标签。

## 四、研究路线与升级门槛

1. **规格冻结**：从原始清单中选择有限、可量化、日线收盘后可得的阶段定义；禁止先看结果再改标签。
2. **独立回测**：确定标的池、复权口径、交易时点、成本、涨跌停/停牌和无法成交的处理。
3. **消融与对照**：至少比较纯 Cycle、趋势回踩、二者并列持有及无规则基准；不能只比较“加了某个 Cycle 过滤器”的结果。
4. **样本外与前向观察**：确认收益并非集中在单一行情或少数极端交易日。
5. **小额模拟运行**：先输出 `cycle_analysis.py` 日报和模拟交易台账；通过预先写明的指标后，才讨论真实预算与自动执行。

未来实现的推荐边界：`src/cycle/` + `cycle_analysis.py`。在此之前，禁止把新的 Cycle 入场或出场规则直接接入 `pullback_analysis.py` / `pullback_sell.py`。
